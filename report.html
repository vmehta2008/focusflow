1 · The goal

What this was actually for

Not a portfolio piece. A tool for a specific problem, for specific people — the author, their family, and the CA Foundation students around them.

The problem

A student sits down with four hours and loses forty minutes deciding what to open. They study the chapter they enjoy. They tick things they half-know. Three weeks later the first chapter has evaporated and nothing tells them.

The insight

Every one of those failures is a memory problem, not a motivation problem. Software is excellent at memory and terrible at motivation — so the app was built to do the first and stay out of the second.

The five goals, set at the start and held to

GoalHow it shows up in the finished thing
🎯 Remove the decidingOne button on the Focus tab names the chapter, weighing overdue revision, weak test scores and exam proximity.
🔁 Remove the forgettingSpaced repetition runs silently. The student never chooses when to revise.
🤝 Meet the student where they areA Telegram bot, because a 17-year-old opens Telegram forty times a day and a study app twice.
💙 Treat the user as a personSleep, meals, training, mood and body sit beside the chapters — a plan built on five hours of sleep is not a plan.
🔒 Own the data completelyNo account, no server, no company holding anyone's marks. The trade is accepted openly: backups are the user's job.

3 · The method

Prompt, build, break, correct

The interesting finding of this project is not the app. It is that the most valuable contribution from a non-programmer was domain correction — catching where the software had quietly assumed a life nobody actually lives.

Every one of the corrections below produced a better product than the original specification would have.
What the author saidWhat it changed
"it took me 30 min to settle down, my brother takes 1 hr" Settle time became a question asked once instead of a hardcoded guess per activity. My values (gym 30, travel 15) were invented; the point was that they're personal.
"not everyone goes to gym" The whole feature was reframed from "commitments" to gaps — twelve shapes including helping at home, prayer, a family shop, rest.
"i lost 7 kg through diet in exam and festive season" Exposed a badly designed alert that flagged a declared, deliberate plan as a symptom. Rewritten to stay quiet when a goal is set and the pace is sane.
"i think a person can go to gym and workout… physical body reads a psychological impact" Training, lifts, personal bests and measurements were added — a whole half of wellbeing that over-caution had left out.
"WILL PREFER NOTEBOOK LM FOR QUIZ ANYDAY" Stopped competing with a better free tool. Built a bridge instead: export notes to it, log the score back.
"CANT WE ADD CLAUDE FOR THE CONCEPTUAL KNOWLEDGE" Model routing by task. Also uncovered a real bug where the same model would have been asked twice and called a second opinion.

The bugs worth naming

CriticalFive Telegram commands crashed with no data

Reading the snapshot without a guard threw an error the moment a student connected the bot before ever opening the app. A thrown webhook returns a 500; Telegram shows the user nothing. This was the cause of "the bot feels broken."

Every read guarded, plus a catch-all that answers with a plain-language apology and returns 200 so Telegram stops retrying.
CriticalThree different failures gave one misleading message

A missing API key, an exhausted quota and a stale snapshot all said "open the app and ask again." Users opened the app, asked again, got the same thing, and concluded it was junk.

Each failure now names itself — including the exact command to fix a missing key.
HarmThe weight alert flagged a deliberate plan

Any loss over 1 kg a week triggered a concern message, including for someone following a goal they had set and told the app about. Concern that ignores what you said is just nagging.

Silent for declared, steady loss. Speaks only when steep or unexplained — and can be dismissed.
HarmOnboarding filed subject names as chapters

The chapters box pre-filled with subject names and rows of dots. Anyone pressing Add without editing got three junk entries on day one, from a box that looked helpful.

Placeholder instead of a value — nothing can be submitted by accident.
DesignA lighter final set reported going backwards

Lift progress compared your latest set to your first, so one deliberate deload set read as regression. Wrong and discouraging.

Measures the ceiling — how much your best has climbed — and notes a deload separately.
DesignAddressed in a group, the bot said nothing at all

Silence in a group chat is indistinguishable from being broken.

An explicit command always gets a reply, with no study data leaked and a pointer to a private chat.
DesignA chapter title with an asterisk killed the whole message

Telegram rejects a message whose Markdown doesn't parse. The reply never arrived — silence again.

Formatting failures resend as plain text. Ugly beats invisible.
5 · Design

The interface, and one hard lesson

Palette

Six pastel card tints — cream, sky, mint, lavender, peach, blush — on a warm off-white gradient. Coral-to-amber for anything the user should press.

Time of day

The background shifts through the day. Night mode collapses the gradients to one flat shade so it doesn't glare at 1am.

Language

Sentences, not labels. "Nothing scheduled until 20:00" instead of "settle buffer: 60".

The lesson. Midway through, an unrequested redesign was applied — flat SaaS surfaces, tighter spacing, muted colour. It was, by conventional standards, more professional. The author rejected it outright and it was reverted in full.

“no i dont like it i am good with mine only… bring back my old ui design”

That was the right call. The pastel scheme is the reason the people it was built for will actually open it. A study app used by a tired seventeen-year-old at eleven at night is not a dashboard, and optimising it like one was a failure of judgement, not of craft. Every design decision after that point was checked against the person, not the convention.

Where data lives

  • localStorage — everything, keyed per profile, so siblings on one device never mix.
  • IndexedDB — photos and voice notes, which are too large for localStorage.
  • Cloudflare KV — a small snapshot only, so the bot can answer when the browser is closed. Names, emails, photos and voice notes are never sent.
  • Nowhere else. No analytics, no telemetry, no account.

Running cost

Hosting: free (GitHub Pages). Bot server: free (Cloudflare's free tier — measured usage is roughly 0.2% of the daily limit). AI: whatever the user's own key costs, on their own account. The project has no running cost to its author, and no way to acquire one.

7 · Honest assessment

What's proven, and what isn't

✅ Proven

  • 266 automated checks passing
  • Every button reaches a handler
  • The bot never goes silent, across 30 hostile cases
  • Clean boot with no data at all
  • A wrong token can't write anyone's data

⚠️ Not yet proven

  • The bot against real Telegram servers
  • Real AI providers, real keys, real quotas
  • Anyone other than the author using it daily
  • The current build is not yet deployed — the live site still runs an older version

Simulated tests prove the logic is sound. They do not prove the plumbing is connected. The remaining work is deployment and one real conversation with the bot.

8 · What was learned

Four things, plainly

Knowing the user beats knowing the tools

The best decisions in this project came from someone who couldn't read the code but knew exactly what a student's evening looks like.

Silence is the worst failure mode

Software that says nothing is indistinguishable from software that is broken. Most of the Telegram rewrite was about never being quiet.

Conventional isn't the same as correct

The "more professional" redesign was the wrong answer for the actual people. Taste that fits your user beats taste that fits a trend.

Use the better tool, don't imitate it

NotebookLM writes better quizzes. The right move was to build a bridge to it, not a worse version of it.
